# Task

## User Request

Use the panel's configured SMTP settings for panel mail, support per-message From addresses, route billing mail through a billing sender, reject missing SMTP configuration, validate the changes, and commit on `testing` without pushing.

## Problem

`mymail()` could overwrite the configured SMTP host with `localhost`, used only the legacy SMTP username key, and had no per-message sender option. Billing messages therefore used the general panel sender.

## Root Cause

The SMTP host fallback was unconditional in the effective flow, and sender selection was embedded directly in `mymail()` without a reusable billing sender policy.

## Architecture Decisions

- Preserve existing callers by adding the optional sender array after the existing `user_to_panel` argument.
- Prefer `smtp_username` and retain `smtp_login` compatibility; use `smtp_passw`, `smtp_port`, `smtp_ssl`, and `smtp_tls` from panel settings.
- Resolve general mail sender from panel/admin/support settings, and billing mail sender from billing settings, with the requested `info@runlevelsystems.com` and `billing@runlevelsystems.com` fallbacks.
- Log and return false when `smtp_server` is empty so mail cannot silently use localhost.
