## Active Billing Model

The current production schema uses invoice-first checkout and an order-backed provisioning queue:

- `gsp_billing_invoices` is the payment and renewal invoice ledger.
- `gsp_billing_orders` is the provisioning and active-service order ledger.
- `gsp_billing_transactions` is the payment transaction audit trail.
- `gsp_server_homes` stores the authoritative server lifecycle state for renewal, expiration, and deletion.
- `gsp_billing_services` is the storefront catalog and maps services to config homes, mods, allowed remote servers, FTP policy, and install method.

Important status split:

- `gsp_billing_invoices.status`: payment visibility/status used by cart and legacy payment paths, with active values such as `due` and `paid`.
- `gsp_billing_invoices.payment_status`: canonical payment state used by repository-based checkout, with enum values `unpaid`, `paid`, `cancelled`, `refunded`.
- `gsp_billing_invoices.billing_status`: renewal lifecycle for the invoice, with active values `due`, `Active`, `Invoiced`, `Expired`.
- `gsp_billing_orders.status`: provisioning/order lifecycle. Active provisioning code selects `Active`; admin code also writes `Invoiced` and `Expired`; older docs/scripts mention `paid` and `in-cart`, but active provisioning does not use those as authoritative.
- `gsp_server_homes.billing_status`: authoritative server renewal lifecycle, with values `Active`, `Invoiced`, `Expired`.
