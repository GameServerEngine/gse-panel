# Changelog

Each fixed issue gets an entry under the version that shipped it: a one-line title, then the cause and the fix in plain language, written so a customer can follow it.

## Unreleased
- **Server status: percentages are whole numbers:** CPU, RAM, disk and availability showed one decimal (8.7%), which was easy to misread as 87%. They are now rounded to the nearest whole number (9%).
- **Game servers can run in Docker containers:** an admin can set a server to Docker on its edit page (image, CPU, RAM, process limit, stop command). Start, stop, restart, status, console and scheduled tasks then use the container on the agent; the customer's panel is the same. Native stays the default, and a Docker server never starts natively by mistake. Needs an agent with container support and database migration 0012.
- **Login: the sign-in page is only the logo and the form on black:** the sign-in form was missing the `login-form` class the Login stylesheet styles, so the boxes were plain browser inputs and did not line up; the logo was drawn twice (once by the Login layout and again by `index.php`); and the layout still printed the theme footer, copyright line, version line and notifications. The form now has its class, `index.php` draws the logo itself only for other themes, the layout no longer prints a footer or notifications, and the leftover closing tags from the removed card wrapper are gone.
- **Billing: pictures for 73 catalog games that had none:** most games added in bulk had no picture, so the storefront showed an empty box. Pictures were fetched from each game's Steam store page (the same header image Steam shows), or from the project's own site or Wikipedia logo for games not on Steam, scaled to at most 600 pixels, and saved in `images/games`. The 118 listings (platform variants share a picture) now point at them. Games still without one: Battlefield 2, Blood Frontier, CSPromod, FiveM, Gearbox, Halo CE, Hidden: Source, the four Medal of Honor servers, Smokin Guns and Spigot Server.
- **Billing: saved PayPal keys are read back, and the save message shows:** the Settings page saved the client id and secret on the `__global__` row, but read them from the oldest row, an empty one from an earlier install, so the form showed nothing and the cart never saw the keys. The reader now takes the `__global__` row first. The "PayPal settings saved" message used styles that only exist on the standalone page, so inside the panel it was not visible; it now uses the panel's own success and error styles.
- **Billing: 0 and 0 slots hides an offer from the order page:** there was no way to stop selling a game at one location without deleting its prices, because the slot range was forced up to at least 1. An offer whose minimum and maximum slots are both 0 is now kept as saved and skipped by the game list, the location list and the order and cart checks. Set real numbers again to sell it.
- **Billing: the cart tells an admin when PayPal has no keys:** with PayPal switched on but no client id or secret saved, the cart showed only the card button and nothing said why. The PayPal button now needs both keys, and an administrator sees a one-line note pointing to Billing > Setting. Customers see no change.
- **Billing: Pay with PayPal sends the customer to PayPal and back:** the cart showed PayPal through a script on the page, which never appeared on a panel with no PayPal keys and was a different flow from the Stripe button. It is now a button like Stripe's: `api/paypal_checkout.php` makes the PayPal order for the unpaid invoices (the cart coupon applies), the customer approves on PayPal, and `paypal/return.php` takes the money through the existing capture code and opens the success page. Cancelling returns to the cart. The old PayPal script and `create_order.php` flow are no longer used by the cart. PayPal still needs its client id and secret saved in Billing > Setting, and is tested in sandbox mode first.
- **Billing: search a game and see competitor prices on the Game Catalog page:** setting a price meant looking up competitors by hand. The top of the page now has a search box that reads gameservercheck.com, lists every hoster's per-slot price for the game, and suggests our price (10% under the lowest PC per-slot price, to the nearest 5 cents). On a game's edit page the box starts with that game's name and "Use this price" fills the per-slot field. Pages are cached for six hours; euro prices are shown as dollars at a rough rate.
- **Assistant: Ask Dave can send ntfy notifications:** the assistant could only answer and offer buttons. It now has `notify_server` (publishes to that server's own topic, made from the server id, so it cannot pick another topic) and, in the admin chat, `notify_admins`. Titles are cut to one plain line so they cannot inject headers.
- **Task Scheduler: a job can start the assistant with a text command:** a new action "Ask the assistant" takes a text command (for example "check the log for crashes and notify me"). The text is saved in a new `assistant_tasks` table and the cron line only carries its id (`api.php?assistant/run`), so long text and quotes cannot break the crontab. A scheduled run uses the same limits as the chat, runs at most once in five minutes, cannot press buttons, and tells people through ntfy or a saved proposal. Administrators' jobs use the admin tools; customers' jobs use the tools of their one server.
- **Billing: the order slider starts at half the maximum:** the slot slider on the order page started at the minimum, so a customer ordering a 100-slot game began at 1 slot. It now starts at 50% of the offer's maximum slots (never below the minimum), computed when the page loads from the offer's own maximum, so no new setting is needed.
- **Billing: 110 more games are for sale:** every game with no offer yet (except bots, voice and test tools) was added to the catalog and enabled. Games whose XML has a Windows block are offered on game3, games with a Linux block on game5 and game6, priced per slot at 10% under the lowest competitor price found (rounded to $0.05), or $0.50 per slot when none was found. Games with 10 players or fewer get one flat price for the full server, 20% under the lowest competitor's full-server price.
- **Billing: PayPal and Stripe have an Enabled checkbox:** both payment methods were offered at checkout as soon as their keys were saved, with no way to switch one off. Each now has an "Enabled" box on Billing > Settings (saved as `billing_paypal_enabled` and `billing_stripe_enabled` in the panel settings). An unchecked method is left out of the cart, the Stripe checkout call and the auto-renew card option; Stripe payment notifications still arrive so refunds and late payments are not lost. A site that never saved the box keeps both on.
- **Billing: Order Options creates its own tables:** the page told the admin to "update the Billing module" when the order option tables were missing, but the tables come from a database step that had not run on this panel. The page now creates the tables itself the first time it is opened. The database step and the page run the same list of statements (`order_options_install_sql`), and the first option is only added once.
- **Billing: messages on Services and Coupons are visible:** both pages wrapped their saved and error messages in `status success` / `status error`, which no stylesheet defines, so a refused save looked like nothing happened. They now use the panel's `success` and `failure` boxes like Order Options. The Services and Order Options pages also say what the difference is: Order Options are extras ticked while ordering a game server, Services are separate requests (support, custom work). The tabs are ordered with daily work first and Settings last.
- **Notifications: the panel is always the first topic, and admins can send a test:** the customer Notifications page listed only the servers a customer owns, but the panel and the agents send their messages to the panel's own ntfy topic (gse-notices), so a customer with no servers saw an error and everyone else could not subscribe to announcements. The page now always lists the panel topic first, then one unique topic per server. The admin Notifications section has a "Send test" link on every topic that publishes a short test message and says whether ntfy accepted it.
- **Cron page: no more warnings for crontab lines that are not jobs:** the cron admin page split every line the agent returned into six parts, so a comment, a `NAME=value` line or an `@reboot` line left the command empty and PHP printed "Undefined array key 5" and "Passing null" warnings. Lines are now split by one helper (`cron_split_job`) that skips anything that is not a normal five-field job.
- **Utilities keeps the two tools that work for any game server:** the Utilities page had tools that tested the wrong thing (traceroute, the speed test and the TCP test ran from the agent against the game server's own machine, the speed test had no endpoint to pick, and several asked for an agent update that does not exist). Network Tools is now Ping and Port Check. Ping fills in your own public IP and accepts any public IP or name; choosing a game server only chooses the agent. Port Check asks the game server's machine which ports it is listening on (`ss` on Linux, `netstat` on Windows) and compares them with the server's game, query and reserved ports, so you see whether the server really opened its ports. Users see listening or not per protocol; admins also see the address, process id and program and can add extra ports. No agent update is needed. The test-target list and speed endpoints are gone from the Diagnostics policy page. A daily download and upload speed (iperf3) for the Statistics page is planned.
- **Notifications: ntfy section for admins:** the admin Notifications page now shows whether the ntfy service runs, its address and port, an Enable switch, an Install button (only when it is not running; it uses a root-owned installer started through one sudo rule) and the topic list (gse-admin, gse-notices and one per game server). Sent notices are also published to ntfy when it is enabled. The topic list read the wrong server columns and printed array warnings; it now reads home_id and home_name.
- **Status history (first slice):** the panel now has the storage for agent resource samples: a 6-hour raw window, hourly and daily rollups that keep each peak and when it happened, and the top five CPU and RAM processes kept for forensics. A poller service asks one agent at a time, round robin.
- **Status history (pages):** the dashboard's green button is now a status table read from the database only: UP/DOWN/UNKNOWN, uptime, last report, CPU/RAM/disk percentages of the whole machine, and today's peaks with their times. Each server has a detail page with the last hour, 24 hours, 7 days and all-time windows, and a complaint lookup (30 minutes either side). Everyone can see the table and the detail pages. Network rates and process names are for admins. The module has an admin settings page for reporting on/off, poll interval and keep times.
- **Agents:** the Linux and Windows agents answer the new `status_sample` call.
- **Server Status page removed:** the dashboard button and the standalone server_status.php page (which called every agent on load) are gone. The dashboard now shows the stored status table. The admin live view on the dashboard (one server, live processes) is unchanged. The storefront footer link to the old page is removed too.
- **Site name beside the logo is a setting:** Settings now has "Show site name next to the logo" (on by default). Turn it off and the panel header and the storefront header show only the logo. The Panel name is still used in emails, invoices and page titles. The storefront header now shows the same name as the panel, and shows no name when the Panel name is blank.
- **Group restart reports success:** restarting servers from a group action reported every restart as failed, because the restart code never returned its success. It now does.
- **Urban Terror installs without our file server:** the Urban Terror 4 game configuration downloaded the game from files.iaregamer.com, which no longer serves it, so an install left a web page where the game should be. It now downloads the official Urban Terror 4.3.4 zip from the game's own site and checks it against the published checksum before unpacking.

## 2.16.4 (2026-11-19)
- **Assistant still missing in Module Manager:** the module list only showed modules that already had a row, and the sync that adds new ones only ran as part of the update. Opening Module Manager now adds every module that is on disk but not in the modules table, so the Assistant appears and can be enabled.
- **Admin assistant has no limits on what it can fix:** a fix is now one change set with any number of steps. A step changes a file on the panel or on any agent (the whole machine, the panel config included), runs an SQL statement on the panel database or any MySQL server, or runs a command on the panel or an agent. The administrator sees every step as a diff, presses Apply, and the steps run in order and stop at the first failure. Undo puts file changes back. The assistant can also read any file on the panel or an agent and run read-only queries on the panel database and every MySQL server. Nothing is hidden from it, so what it reads is sent to the AI provider. The admin switches for files, edits and resets, and the folder lists, no longer apply to the admin assistant. PHP files must still pass a syntax check before they are written.
- **LiteFM on the panel's own files is the same file manager customers use:** Admin > LiteFM has a button that opens the normal LiteFM with the panel folder as the server. View, edit, download, upload, rename, copy, move, compress and delete all work and can be used to test LiteFM itself. Every change to an existing file keeps a copy in logs/litefm-backups, and a PHP file that fails the syntax check is not saved.

## 2.10.0 (2026-11-14)
- **83 new games:** 72 games from LinuxGSM that the panel did not have (for example Counter-Strike 2, Palworld, Satisfactory, Project Zomboid, Soulmask, The Front, Core Keeper, Barotrauma, Minecraft Bedrock, PaperMC and Vintage Story) and 11 that other hosts sell (for example ARK: Survival Ascended, Enshrouded, V Rising, Sons Of The Forest and Icarus). LinuxGSM is used as the source of truth for Linux: the install, executable and start options come from its configs, and each file says at the top where it came from and what is left to do. Windows blocks and the 11 other games are written from Steam's launch data and each game's documented options; none are tested on an agent yet. New tools in `tools/lgsm_xml/` regenerate and check the files.
- **Space Engineers installed the wrong game:** Its XML used Steam app 950900, which is Operation: Harsh Doorstop. It now uses 298740, the Space Engineers Dedicated Server.
- **Counter-Strike 1.6 could not install on Linux:** The Linux block had no Steam app id, so SteamCMD was asked for an app called "cstrike". It now installs HLDS (app 90) with the cstrike mod, like Windows.
- **Start lines with an unfilled value:** Arma 3 on Linux started with a literal `%PROFILES%`, Life is Feudal on Windows passed a literal `%PORT%` as the world id, and Rust on Windows passed a literal `%SECURE%`. Arma 3 now uses `-profiles=profile` (as on Windows), Life is Feudal uses world 1, and Rust on Windows has the Valve Anti-Cheat setting the Linux block already had.
- **Outdated Linux executables:** Team Fortress 2 now runs the 64-bit `srcds_run_64`, Natural Selection 2 runs `x64/server_linux` (the 32-bit build is gone), and Operation: Harsh Doorstop runs `HarshDoorstop/Binaries/Linux/HarshDoorstopServer-Linux-Shipping`, matching LinuxGSM.
- **Source and GoldSrc servers could take another server's ports:** Two servers on one machine both used the default client port (27005) and SourceTV port (27020), and a server whose port was busy quietly moved to the next one. The Linux start lines of 28 Source and GoldSrc games now add LinuxGSM's `-strictportbind`, a reserved `+clientport` and (Source) `+tv_port`. They also add `-norestart`, so a crash is handled by the agent's watchdog instead of being restarted unseen by `srcds_run` or `hlds_run`.
- **Conan Exiles, Colony Survival, DayZ, Eco and Wurm Unlimited can run on Linux:** They had only a Windows block. Their Windows settings were moved into the Windows block (the panel sees exactly the same Windows settings as before) and a Linux block from LinuxGSM was added.
- **Non-Steam installs ran in the wrong folder:** For games that install with a script instead of SteamCMD (for example Minecraft), the install script ran in the agent's own folder, so files such as `server.jar` were downloaded to the wrong place. The script now runs in the game folder, as SteamCMD installs already did.
- **Every start and restart failed with an SQL error:** The server's mod settings were read before they were merged in, so a query was built with an empty mod id and MySQL rejected it (this also broke "Start selected"). The mod settings are now merged first.
- **Inline start said "No game port is configured":** The start panel on the game monitor never received the server's port, even when one was set. It does now, and a FAILED or CRASHED reason shows on its own line instead of covering the address.
